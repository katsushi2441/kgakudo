# Kurage 学童保育ナビ（kgakudo）

住所を入れると、その自治体の放課後児童クラブ（学童保育）のクラブ数・登録児童数・待機児童数が出ます。

**公開: https://kurage.exbridge.jp/kgakudo.php/**

**PHP 1ファイルとJSONだけで動きます。** データベースも常駐サーバーもポートも使いません。
判定に使うデータは約29KB（129自治体＋待機50人以上の88市町村）で、年1回しか変わらないからです。
Pythonが要るのは年1回のPDF取り込みだけで、製品には含めません。

## なぜ作るか（2026-09-21 実測）

こども家庭庁は毎年「放課後児童健全育成事業（放課後児童クラブ）の実施状況」を全国調査している。
ところが公表の形がこうなっている。

- **PDFだけ。** 令和5年・6年・7年・令和8年度速報のどれにも Excel も CSV も無い。
- **e-Stat に載っていない。** 業務統計のページに「e-Statに掲載されていない」と明記され、
  データベース／XML／CSV／Excel／PDF の全欄が「なし」。
- 表の粒度は **都道府県47＋指定都市・中核市等82**。調査は市区町村単位で取っている
  （令和7年は1,633市区町村が実施）のに、市区町村名で出ているのは
  **待機児童が50人以上いる88市町村だけ**。

令和7年5月1日現在の全国の待機児童は **16,330人**。そのうち88市町村ぶんが 11,208人なので、
**残る 5,122人（31%）は、どの市町村のものか国の公表からは分からない。**

保護者が「自分の市の学童は足りているのか」を国の資料から引けない。ここを開く。

## いま出来ていること

`scripts/parse_cfa.py` が PDF から3つの表を取り出して JSON にする。
**合計はPDFの全国値と完全に一致する**（待機16,330／クラブ25,928／登録1,570,645）＝抽出が正しい証拠。

    /usr/bin/python3 scripts/parse_cfa.py data/raw/r7_2025_jittai.pdf --year 2025
    /usr/bin/python3 scripts/to_csv.py --year 2025

出力:
- `data/gakudo_2025.json` … 129自治体（都道府県・指定都市・中核市等）＋待機50人以上の88市町村
- `data/gakudo_areas_2025.csv` / `data/gakudo_waiting50_2025.csv` … 国が出していない形

## 置き方（買った人がやること）

1. `php/kgakudo.php` と `php/kgakudo_data/` をサーバーに置く
2. その階層の `.htaccess` に `AddHandler php-script .php`（heteml は既定が PHP 5.6 なので必要）
3. 以上。データベースも外部サーバーも要らない

## 画面

- `/` 住所を入れて判定（3通りに書き分ける: 市の数字／待機50人以上の一覧にある／未公表）
- `/waiting50` 待機が50人以上の88市町村
- `/area/<自治体名>` 129自治体の受け皿ページ
- `/data` CSV・JSONの配布、`/api/check?q=住所` でJSON
- `/about` 出どころと、なぜ市区町村別が無いのか

## これから

1. 年次比較（令和5〜7年＋令和8年速報）— 同じパーサーで JSON を増やす
2. kappstore への出品（PHPを置くだけ、の形で売れる）
3. 国会議員向けの資料（CSV＋「市区町村別をCSVで公表してほしい」の論点）

## 原則

- 数字を作らない。国が出していないものは「未公表」と書く（[[feedback_uncovered_means_not_judged]] と同じ作法）。
- 出典と時点を画面に出す。こども家庭庁の調査であることを明記する。
